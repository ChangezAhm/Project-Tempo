# Rule Ledger

**Status:** Living registry, created at the Phase-2 gate (2026-08-05). Companion to `docs/Fill-Plan-Architecture.md` (§1 authority model, §4 disposition table, §8 anti-bloat rules).

This is the permanent registry of every surviving **non-fact rule** in `parser/app`. Facts (cell values, formulas, number formats, dependency graph, protection/colours as *data*), intent judgments (the LLM's, via the Fill Plan), and learned decisions (the Template Contract) are not listed — only the code that *decides* something on its own.

**The PR rule:** a PR that adds a rule must add a row here, with multi-template evidence that the rule holds generally. Review rejects intent-judgments-as-code — a failing file produces (in order) a contract decision, a prompt/prior improvement, or a new verifier error code; a new global rule is the last resort. (See §8.2/§8.4 of the architecture doc.)

**Kinds:**

- **Constraint** — a safety invariant; violation is never acceptable. Blocks or refuses, with a structured, visible reason. Examples: no partial quarter-sums, the double-count guard, % never scaled into money, template totals never written, formula/error strings never written.
- **Prior** — a default about author intent: advisory or tie-breaking only, and always visible/flagged when it decides. A prior that decides silently is a bug (that was the pre-migration defect).

**"Overridable by"** names what can legitimately beat the rule: `nothing (constraint)`, `user decision` (an answered review item), `contract decision` (a persisted decision replayed onto the plan), `LLM judgment` (the planner/enrichment owns the call; the rule only ranks or corroborates), or a config/env knob.
